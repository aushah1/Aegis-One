# Difficulties we faced
One line per real obstacle, in the order we hit them: what broke, what we tried, what worked. Written during the hackathon (Fri Oct 23 to Sun Oct 25); the step numbers point into [PLAN.md](PLAN.md).

- **Running Gemma in the browser vs. on the computer.** Plan v2 ran Gemma 4 inside Chrome (Transformers.js + WebGPU). We first switched to Ollama on the demo Mac (simpler, faster on 24 GB, but the user has to install it), then got Gemma 4 E2B running inside Chrome with Google's LiteRT-LM (WebGPU), which became the main download on Saturday. Ollama is the fallback.
- **Ollama blocked the extension (HTTP 403).** Ollama only accepts requests from approved origins. Fix: `launchctl setenv OLLAMA_ORIGINS "chrome-extension://*"` and restart Ollama.
- **Gemma for cookie banners was the wrong tool.** A teammate pointed out the page's own JavaScript finds the Reject button faster and more reliably, so Gemma moved to answering questions and (next) reading policies.
- **RegTrack data is 1.5 TB on Globus.** Dropped the download; we use the paper's published figures with section numbers.
- **13 hard-coded trackers missed most real tracking.** Built shared/atlas.json from DuckDuckGo Tracker Radar (21,000 domains filtered to the 3,721 that track), including uncategorized domains that fingerprint or set cookies (that's how TikTok/ByteDance and Baidu got in).
- **Google looked "risky" on its own homepage.** Google's own trackers counted as third parties, and "no cookie banner" cost points even with nothing to refuse. Fixes: same-company requests don't count; unknowns add 0; points only when you weren't given a choice.
- **Keeping data current without breaking privacy.** Looking up each site in a breach database would reveal your browsing. We download the whole breach and broker lists daily and match locally.
- **Gemma mislabels sources.** It invented tags like "[Sites visited]" and wrote "the user". Code now cleans tags and wording after Gemma answers, and every evidence line carries its tag.
- **Two parts writing the same storage at once.** The cookie detector and the tracker recorder could overwrite each other's results. All writes now go through the background script in order (the last direct write, from the cookie detector, moved there on Saturday).
- **Teamwork with beginners on Git.** Zip uploads, a scary "force push" prompt, and lock files. Rules now: pull first, push code not zips, never force push.
- **"Did the decline really work?" Every consent tool saves your choice differently.** C could only confirm OneTrust, so most sites got "couldn't verify". Now it reads the yes/no from five tools' own records (never storing them). Some banners (Tesco) slide out of view but stay in the page, which C first took as a failed click.
- **Pop-ups C can't see.** Some consent tools live in a shadow root (now searched) or an iframe (Sourcepoint, TrustArc). Content scripts normally run only in the top page, so the cookie detector now also runs in frames and tells the top page where the Reject button is.
- **Chrome forgets tab state.** Chrome pauses the background script when idle, so trackers could be missed afterwards. Fixed: tab state is mirrored to session storage and survives the pause.
- **Loading Gemma froze Chrome.** Right after C's brain downloaded, every tab stopped drawing for 15-20 s while the runtime built about 150 graphics programs with a blocking call. The fix (merged Saturday evening) does a quick practice load to find the programs, then builds them the non-blocking way first.
- **C stayed silent on busy pages.** The re-check timer restarted on every page change, so pages that never stop changing were never re-checked. Re-checks now run at most every 350 ms, and also when a pop-up is shown later by a style change.
- **An honest grade can't be a harsh one by default.** A teammate's 21-check scale gave every unknown half the points, so with what a browser can see nearly every site got an F. We kept our scale (unknowns add 0) and borrowed its best parts: each grade now shows its best/worst range if the unknowns were checked, how much of the rubric was checked, and a "Fully/Partly checked" label.
- **A security review of our own code.** Before the Chrome Web Store, an audit found that a site's "Privacy" link could forward Aegis One's request to a home-network address, a page was re-fetched on every visit while the AI wasn't set up, and old history waited for your next visit to be deleted. Each got a failing test first, then a fix (docs/STORE.md section 6).
- **A small AI that fills gaps from memory.** Gemma 4 E2B sometimes skipped evidence it was given and filled in from general knowledge: "Facebook has a history of data breaches" (no record), "ByteDance is on the Pentagon 1260H list" (it isn't), "you accepted all cookies" after a "why?" (you hadn't). Fixing each wording didn't end, so we fixed it the general way: questions with a factual answer (grades, breaches, "Is X safe?", "Does X sell my data?") are answered by code from the records, and every Gemma answer is checked afterwards (sentences naming a company or breach that isn't in the evidence are dropped). A backtest of about 150 wordings and follow-ups found 8 more root causes (PLAN R13, R19, docs/ASKC-FIXES.md).
- **Reading a policy honestly.** The policy reader saved "sells your data" from "We sell premium advertising space" (bbc) and "We sell premium Services" (linkedin), adding 15 points to each grade. A "sells" answer now needs a sentence that really says so, and saved answers are checked again each time Aegis One starts.
- **The same Gemma, ten times slower on Windows.** On a laptop with two graphics chips, Chrome on Windows ignores the request for the fast chip, so answers took 18-70 s instead of about 2 s. Windows' own graphics setting for Chrome (High performance) fixes it; the setup guide and C's brain card say so (docs/IN-BROWSER-AI.md).
- **Windows line endings.** Git on Windows checked files out with different line endings, and tests that compare files exactly failed there. A `.gitattributes` file keeps the same endings on every computer.
- **Red errors on chrome://extensions.** The AI runtime's log lines, a reloaded extension's leftover scripts in open tabs, and normal "banner did not disappear" notes all showed as errors. Each one is now a plain log or retires cleanly, so judges see a clean extension page.
- **Testing real sites from the cloud.** Our cloud coding sessions couldn't open most websites, so every real-site check ran in Chrome on the Mac and on the Windows laptop: 22 sites and 42 Ask C questions with the real in-browser Gemma the night before submission, and their results drove the last round of fixes.
